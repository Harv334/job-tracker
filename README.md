# Job Tracker

A personal dashboard for the job search. Tracks every application, draws a
Sankey diagram of the funnel, and tells you which CV version is actually
landing interviews.

## Features

- **Sankey funnel** — Applied → Phone screen → Hiring manager → Technical → Onsite → Offer / Rejected / Ghosted, with thickness proportional to count.
- **KPI tiles** — total applications, response rate, interview rate, onsite rate, offer rate, ghost rate, median days to first response, median days to outcome.
- **Breakdowns** — by sector, source, company stage, and CV-version effectiveness (interview/offer rate per CV).
- **Searchable, filterable table** with stale-application indicators (no activity in 14+ days).
- **Public/private data switching** — keep real data local, deploy an anonymized version.

## Stack

Vite + TypeScript + Tailwind, D3 (Sankey), Chart.js (breakdowns). No backend; data lives in JSON files in this repo.

## Running locally

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # outputs to dist/
```

## Adding applications

For now, edit `data/applications.sample.json` (or your private file — see below). Each application looks like:

```jsonc
{
  "id": "2026-04-20-acme-pm",
  "company": "Acme",
  "role": "Senior PM",
  "sector": "fintech",
  "company_stage": "series-b",
  "company_size": "100-500",
  "location": "Remote",
  "source": "referral",
  "cv_version": "v3-product",
  "applied_date": "2026-04-20",
  "current_status": "phone-screen",
  "stages": [
    { "stage": "applied",      "date": "2026-04-20" },
    { "stage": "phone-screen", "date": "2026-04-25" }
  ],
  "salary_range": [150000, 180000],
  "notes": "Met at conference"
}
```

CV versions are listed in `data/cvs.json` — add new versions there and reference them by `id` in applications.

## Public vs private data

The site loads data in this priority order:

1. `data/applications.private.json` — your real data, gitignored. Use this while you're job-hunting privately.
2. `data/applications.public.json` — generated by the anonymizer (`npm run build:public`). Strips company names, salaries, notes, links — keeps stages, dates, and CV versions so all the stats still work.
3. `data/applications.sample.json` — bundled fake data, shipped in this repo so the demo works for anyone who clones it.

To go public-anonymized:

```bash
cp data/applications.sample.json data/applications.private.json   # or your own
# edit data/applications.private.json with your real data
npm run build:public
git add data/applications.public.json
git commit -m "Refresh public data"
git push
```

The deploy workflow runs `build:public` automatically (no-op if no private file is present), so you can also keep the private file out of the repo entirely and only generate the public file on your local machine.

## Deploying to GitHub Pages

1. Push this repo to GitHub.
2. In the repo settings → Pages, set **Source** to "GitHub Actions".
3. Push to `main` — the workflow at `.github/workflows/deploy.yml` builds and deploys.

The base path is set automatically from the repo name, so `https://<user>.github.io/<repo>/` will work without further config.

## Migrating to private hosting later (Azure)

The whole site is a static Vite build that drops onto **Azure Static Web Apps** with no code changes. When you're ready:

1. Create a Static Web App in Azure (Free tier works).
2. Replace `.github/workflows/deploy.yml` with the workflow Azure generates for you.
3. Set authentication on the SWA so only you can view it (Easy Auth + role assignment).
4. Move `applications.private.json` into the build (or ship it as the only data file) — now your real data is behind auth.

Nothing in the app code needs to change; only the deploy pipeline.

## Data privacy reminder

The `.gitignore` excludes `data/applications.private.json` and `data/cvs.private.json`. Don't rename these files without updating the gitignore. Run `git status` before every push.
